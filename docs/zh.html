为什么这件事突然变成刚需

不是因为 AI 更能找 bug 了，是因为用云端工具审代码这件事，在很多场景下已经不合规。

合规底线

源码出境要过评估

《数据安全法》《促进和规范数据跨境流动规定》之下，把核心源码交给境外云端 AI 工具，很多场景需要先完成安全评估。等保 2.0 对核心系统代码的传输与存储也有明确管控要求。

供应链风险

境外工具后门预警

工信部网络安全监测平台已就境外 AI 编程工具的数据回传风险发布预警，要求政企与关键行业停用未完成国内合规备案的海外 AI 开发工具，优先采购可本地存储的国产方案。

乙方处境

甲方合同里写了“不得上云”

给金融、政务、央国企做外包的团队，合同里的数据条款往往直接禁止把代码放到第三方云。但团队又想用 AI 提效——这就是缺口所在：既要 AI，又不能上云。

常见问题

代码会不会被传到你们服务器？CLI 和 App 有区别吗？

分两种接入方式。CLI 和私有化部署：不经过我们。diff 从你的机器直接发给你配置的模型服务商（DeepSeek、Qwen、GLM 这些），或者你内网自己的 Ollama——后者可以断网跑，代码连内网都不出。GitHub App：会经过我们的服务器（app.revhive.souljian.cn），我们把 diff 转给你配置的厂商，但不写入我们的数据库。库里留的只有审查摘要——仓库名、PR 号、风险分、发现数量和时间。

必须要有 GPU 吗？

不需要。用 DeepSeek、Qwen、GLM 的 API 就不需要 GPU，只付 token 钱。完全离线才需要本地推理，显存需求取决于模型大小和 diff 规模。CLI 的 ollama preset 默认是 qwen2.5-coder:7b（src/revhive/config.py），Docker 部署默认是 qwen2.5-coder:14b（deploy/docker-compose.ollama.yml），首次启动约下载 9 GB（仓库注释里的估算）。14B 级别在通用代码审查上能用，但对复杂业务逻辑的推断弱于云端大模型；70B 以上效果更好，需要 40G+ 显存。这一段在我们的私有化部署方案里写过。

能接我们自己的 GitLab / Gitea 吗？

内置是 GitHub App 和 CLI 两种接入。内网 GitLab / Gitea 走 CLI + CI 方式接入，私有化交付里我们帮你接好。这一项按你的环境现场确认。

它会不会像别的工具一样天天误报？

会，取决于模型和规则。所以我们不承诺“零误报”，我们承诺你可以调：Agent 的提示词、严重度阈值、门禁分数线全部在配置文件里，改完即时生效。私有化交付里，规则是照你的代码规范写的。

为什么这么便宜？

因为 token 钱你自己付，我们不承担推理成本，也就不需要靠订阅费覆盖算力。你付的是工具本身的价钱。
